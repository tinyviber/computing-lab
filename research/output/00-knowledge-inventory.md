## 0. 结论摘要（TL;DR）

1. **当前 3 个实验**：图像编码（`/labs/image-encoding`）、声音编码（`/labs/audio-encoding`）、家庭网络配置（`/labs/home-network`）。
2. **与必修一教材的对应关系**：前两个部分覆盖**项目二"认识数据编码"**中的"声音数字化"和"图像数字化"两个知识点；**家庭网络配置不在必修一教材中**（属网络主题，对应其他模块）。
3. **覆盖程度**：没有任何知识点达到"完整覆盖"；**部分覆盖 2 个知识点（声音/图像数字化，且各缺重要维度）、未覆盖 62 个知识点条目**。未覆盖范围覆盖第一单元其余内容、第二、三、四单元全部内容。
4. **已有实验帮助学生理解的抽象概念**（详见 §2）：连续信号→离散样本、幅度量化→有限级数、数据量=采样数×位数、像素网格与调色板、量化误差/重建失真、参数-可视化实时联动。
5. **可复用资产**：一套完整的"滑块参数 → 实时可视化 → 公式面板 → 实验状态机"交互范式，7 个 shared/lab 组件、三层架构（domain/lesson/ui）、URL 场景共享机制（详见 §4）。
6. **天然不适合网页实验的知识点**：概念辨析/伦理讨论类、真实工具操作类（问卷平台、Excel/WPS、Python+MNIST 训练、AI 风格迁移）、实地调查类（详见 §5.1）。同时存在一批**天然适合网页交互、但当前未覆盖**的知识点（如实标注适合度，不展开设计，见 §3 各条）。

## 2. computing-lab 现状解剖（已实现内容）

### 2.1 项目定位与技术形态

- README 定位："Interactive high-school computing lessons. Local-first, static Vite app, no account or backend."
- 技术栈：Vite + React 19 + TypeScript + TanStack Router + Vitest + Playwright，Bun 包管理（React 版本已按 package.json `^19.1.1` 核实）。
- 路由：`/`（实验注册首页）+ 3 条实验路由；每条路由带独立 `LabErrorPage` 错误边界。
- 教学模型（AGENTS.md）："Prefer explicit formulas and observable state"——显式公式 + 可观察状态；场景可编码进 URL 便于教师分享复现；用户输入在 domain 边界校验与钳制。
- ⚠️ 重要背景：`docs/course-model-reset.md` 是**已冻结的迁移设计文档**（代码尚未实施）。它裁定：当前 shared 层的 `phase/step/submit` 等概念是"过早抽象"，三门课没有共同的 lesson workflow；未来将把 `LabShell` 收敛为仅 app chrome + opaque `children`，把 `FormulaPanel/ParameterControl/VisualizationPanel/ExperimentStatus` 降级为 feature-local，并按"声音 → 网络 → 图像"顺序重做。**因此本文 §4 所列"可复用范式"应理解为"当前代码事实"而非"项目认定的长期架构方向"。**

### 2.2 三个实验逐一解剖

#### 实验 A：图像编码（`/labs/image-encoding`，category=信息编码）

| 维度           | 内容                                                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 教什么抽象概念 | 图像数字化的两个独立维度：**空间采样（分辨率代理）**与**幅度量化（颜色位深度代理）**；二者共同决定数据量；量化引入信息损失（源色→最近调色板色）                                                    |
| 教学载体       | 8×8 的 16 色源图像 fixture → 按密度采样 → 按 bits 构建确定性调色板（按亮度排序的源色子集）→ 最近邻量化 → 像素网格显示                                                                              |
| 交互控件       | 2 个滑块：Sampling density（2–8）、Quantization bits（2–8 bit）                                                                                                                                    |
| 可视化         | 动态 `density×density` 像素网格（div grid），每格可读"源色/调色板索引/显示色"；图例区分 Source sample / Quantized display；6 项统计（采样像素数、位数、编码 bits/bytes、原始基线、理论像素载荷比） |
| 公式面板       | Raw baseline（8×8×24bit）→ Indexed payload（像素数×bits）→ Encoded bytes（÷8 取整）                                                                                                                |
| 状态机         | ready → editing（动滑块或 Run preview）→ success（仅 density=4 且 bits=8）/ failure（其他组合）；retry / reset / next-step                                                                         |
| 工作流         | 4 步步骤条：Observe sampling → Adjust quantization → Calculate encoded payload → Write conclusion（第 4 步是"写结论"，实际 UI 中为占位步骤）                                                       |
| 场景共享       | `?scenario=low-sampling                                                                                                                                                                            | high-quantization&density=&bits=`，解析链 default → preset → explicit → clamp(2..8) |
| 对应教材       | 项目二"图像数字化"（P24-25 知识链接、活动 2.4、图 1-25 位图比较）                                                                                                                                  |

**帮助学生理解的抽象**：像素是图像的最小单元；"分辨率×色深"共同决定存储量；量化是把连续颜色"近似"到有限集合的过程——实验用图例与网格把教材图 1-25（不同分辨率/位深度位图比较）变成了可交互操作。

#### 实验 B：声音编码（`/labs/audio-encoding`，category=信息编码）

| 维度           | 内容                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| 教什么抽象概念 | 声音数字化三要素中的两个：**采样率**与**量化位数**（+ 信号频率）；连续波形→离散样本→有限量化级→重建阶梯失真的完整链路 |
| 教学载体       | 1 秒正弦波 fixture（1–8 Hz），按采样率取点，按 2^bits 级量化，重建折线波形                                            |
| 交互控件       | 3 个滑块：Frequency（1–8 Hz）、Sampling rate（8–32 /s）、Quantization bits（2–8 bit）                                 |
| 可视化         | SVG 折线波形（源波形 vs 量化重建）；4 项统计（样本/秒、振幅级数 2^bits、编码 bits/bytes）                             |
| 公式面板       | Samples × bits → bytes；附带当前 preset 名                                                                            |
| 状态机         | 仅 ready/editing 两态（无 success/failure 判定），是"自由探索型"实验                                                  |
| 场景共享       | `?scenario=low-frequency                                                                                              | low-bits&frequency=&rate | sampleRate=&bits=` |
| 对应教材       | 项目二"声音数字化"（P23-24 知识链接、活动 2.3、图 1-18/1-19 采样与量化过程）                                          |
| 注意           | **无真实音频播放**（无 Web Audio/音轨），只有 SVG 波形可视化与统计数字                                                |

**帮助学生理解的抽象**：采样是"按时间等距取幅度值"（教材图 1-18）；量化是把幅度范围分成 2^n 级后近似（教材图 1-19 的"真实幅度 5.4→级数 5"）——实验用滑块让这两个过程即时可见，并直接展示"采样率/位数越低，重建波形越粗糙"。

#### 实验 C：家庭网络配置（`/labs/home-network`，category=网络）

| 维度           | 内容                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |

## 3. 教材知识点 × 覆盖情况 Inventory（核心）

**覆盖等级定义**：

- 🟢 **完整覆盖**：实验直接、基本完整地呈现该知识点的核心机制，学生通过操作能理解其主要抽象。
- 🟡 **部分覆盖**：实验覆盖了该知识点的部分核心维度（通常 1–2 个参数/机制），其他重要维度未呈现。
- 🔴 **未覆盖**：项目中无任何内容与之对应。
- 适合度列：判断该知识点是否**天然适合**做成"参数化、可观察、可交互"的网页实验（事实性判断，非设计提案）。N/A = 不适合或意义有限。

- **对每门课的自然模型的描述**（可作为"已有实验帮助理解什么抽象"的对照）：
  - 图像编码：source → spatial sampling → color quantization/palette → encoded representation → reconstruction + visible loss；无全局正确配置，不应有 step/submit。

  - 家庭网络：connect → address → subnet decision → gateway → route/NAT → 故障定位（first failing hop）；不是"网关文本框 + submit"。
- **计划动作**：`LabShell` 保留 app chrome（branding、catalog 导航、响应式、可访问性、error isolation），workspace API 收敛为 opaque `children`；删除共享 `phase/step/submit/retry/next-step` 与固定四插槽；`FormulaPanel/ParameterControl/VisualizationPanel/ExperimentStatus` 移回 feature 或降级为 neutral helper；迁移顺序为声音 → 网络 → 图像。
- **对 inventory 的意义**：§4.1 的范式（P3 状态机、P4 步骤条、P7 教学尺度）中有三课共性被项目自身证伪的部分；如实引用时需区分"代码现状"与"已冻结的方向"。

## 5. 观察与边界

### 5.1 天然不适合网页"参数化交互实验"的知识点（需如实标注）

以下知识点在教材中的定位是**概念辨析、伦理讨论、真实工具操作或实地调查**，其学习机制不是"调参数看现象"，纯静态网页实验难以等价替代（适合做阅读材料、讨论支架、测验，而非交互实验）：

- **概念/思辨类**：1.1–1.5（数据/信息/知识、特征、大数据 4V、数据安全法）、2.1/2.13（数据处理作用、数据保护观念）、3.1/3.2/3.5（算法与程序的概念、特征、评价）、4.1/4.8/4.9（AI 概念与阶段、分类回归与监督学习概念、AI 伦理与影响）。
- **真实工具操作类**：2.3（数据采集工具认知）、2.14 与单元挑战（气象数据采集需上网+电子表格）、1.20（二维码制作需外部工具）、3.8（Python 编程实操——需要代码编辑/执行环境，与现有"滑块-可视化"范式是两种不同的交互形态，浏览器内可做（如 Pyodide）但属于新的平台能力，当前不存在）、4.4/4.6（真实 MNIST/CNN 训练需 Python+算力，但**训练过程的模拟/可视化**是另一回事，见适合度列）、4.10（神经风格迁移需预训练模型与 GPU，纯前端轻量演示意义有限）。

### 5.2 结构性观察（事实）

1. **教材错位**：`home-network` 实验与必修一教材无对应知识点（其 category"网络"也不在教材单元结构中）；catalog 的 category（"信息编码""网络"）按主题粗分，与教材"单元→项目"结构不对齐。
2. **覆盖集中度**：必修一覆盖仅集中在项目二的两个数字化知识点（且均为部分覆盖）；第二、三、四单元在教材中约占 2/3 篇幅，当前覆盖为零。
3. **部分覆盖的具体缺口**：
   - 声音数字化缺"声道数"（教材三要素之一）与真实量级、听感、编码格式；
   - 图像数字化缺真实图片、格式/压缩、文件大小概念（实验 UI 已明示排除这些因素）。
4. **教学闭环不一致**：三个实验的状态机深度不同（图像编码 4 步+判定；声音编码无判定；家庭网络仅判定），"实验完成"的判定标准尚未统一。
5. **语言混用**：UI 文案中英文混杂（页面标题中文、步骤标题英文、说明中英文混排），反映当前处于开发期。
6. **判定关卡与知识点解耦**：图像编码的 success 条件是固定组合（density=4, bits=8），属于教学关卡设计而非教材知识结论。
7. **共享层地位存在内部争议**：项目自己的冻结文档（course-model-reset.md）判定当前 shared workflow 是过早抽象并计划拆解；因此"可复用范式"清单（§4）是代码事实，不是项目认定的长期方向。
8. **声音实验缺时间维度**：当前声音编码无播放/试听/scrub/A-B（只有 SVG 波形），而冻结文档认定 playback 是声音课程的核心；这也解释了 1.13 覆盖度的"部分"性质。
9. **URL 为只读 transport**：调整控件不写回 URL，场景共享依赖手工构造/分享链接。
10. **适合度标记为"高"的未覆盖知识点**（供未来规划参考，不构成设计提案）：进制转换（1.7）、流程图与控制结构（3.3/3.4）、累加与循环构建（3.11）、随机投点法算 π（3.12）、表格公式/排序/筛选/透视表（2.9–2.12）、枚举法与密码锁（3.21/3.22）、图像向量化与训练曲线（4.5/4.6）。这些知识点与现有"参数-可视化-公式"范式亲和，但本 inventory 不展开任何实验设计。
11. **站点元信息滞后**：`index.html` 的 `<title>`/`description` 仍停留在"图像编码"时代（"Computing Lab 图像编码: a precise, local pixel color compression workspace."），与三实验现状不符——文档一致性瑕疵（代码核实）。
12. **声音实验无真实播放已确认**：全仓库无 `AudioContext`/`<audio>`/`.play()`（grep 核实），"试听"仅是 course-model-reset 的未来设想。
