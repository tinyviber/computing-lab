# 图像编码实验优化记录

## 这次要解决的问题

旧页面把图像编码当成连续开放探索，并用一份很长的任务清单记录多个观察。第一次进入页面时，学生同时面对采样、相位、视图、颜色和数据量，操作顺序不够清楚；URL 里的参数也容易让页面看起来像已经完成了部分任务。

现在页面使用 feature-local 的四步流程：

1. 改变空间采样百分比；
2. 选择调色板或原色，并在调色板模式下调整位深；
3. 选择未压缩 / 原始、PNG、JPG / JPEG 或 WebP；
4. 编辑宽度、高度或每像素位数，计算准确的原始位数和原始字节。

初始页面允许操作采样百分比和上传图片。其他课程控件会显示锁定状态，并由 reducer 再次检查前置条件。采样值发生真实变化后，视图、画布位置选择和相位开放；完成颜色步骤后开放格式；选择格式后开放计算器。

## 样例图片的选择

预设图片使用一张项目内生成的小猫图像，固定为 `240 × 160` RGB 栅格。图像随代码发布，不依赖远程文件。

选择它的理由：

- 深色背景与白色毛发形成清晰轮廓，降低采样后仍能看出主体变化。
- 两只颜色不同的眼睛和毛发边缘同时提供颜色差异、细节差异和局部高对比区域。
- 小猫插图是学生容易识别的画面，比抽象色块更容易引出“哪些信息先消失”的讨论。

## 从生成图像到本地样例

图片在开发阶段生成一次，随后按以下步骤处理：

1. 将图像固定为 `240 × 160`，给采样滑杆留下可见的变化空间。
2. 转换成 8-bit RGB 原始像素。
3. 将 RGB 字节以内嵌 Base64 形式写入 `src/features/image-encoding/domain/photo-rgb.ts`。
4. 运行时直接从本地字节生成 `RasterImage`，不请求远程图片、不依赖外部 CDN，也不把图片写入 URL。
5. 用稳定像素签名、颜色数量、相邻像素差异和采样/颜色数量变化测试确认结果可重复。

## 课堂界面取舍

- 首页保持中性目录，不推荐图像编码或显示专属预览。
- 图像实验的可见内置素材只有“小猫插图”。本地上传从首屏可用；成功上传会清空本节进度并重新开始，失败只显示错误，不重置当前实验。
- 旧的 `image=gradient`、`image=checkerboard`、`image=text-edge` 和 `image=pixel-grid` URL 仍可解析，便于兼容旧链接和定向实验，但不再向学生展示长选项列表。
- 默认颜色表示为原色 RGB24；只有完成采样步骤后，调色板和位深控件才可用。旧链接中的 `color=palette` 只兼容读取为 RGB24，序列化时不再写入颜色参数。
- 四步清单只展示当前步骤和解锁状态；第 4 步在用户编辑至少一个计算器字段后才显示“已完成”。

## 数据量边界

原始像素数据量继续使用：

```text
rawBits = width × height × bitsPerPixel
rawBytes = ceil(rawBits / 8)
```

格式选择保留为概念入口，但不为 PNG、JPG / JPEG 或 WebP 编造字节数。它们的实际文件大小会随图像内容、编码器设置、文件头、颜色表、元数据和格式实现变化。

## 人话审查记录

用户可见文案统一使用“当前图像”“原始数据量”“原始位数”“原始字节”“已完成”和“待解锁”等直接说法。页面不把压缩格式写成固定文件大小，也不把四步流程包装成计分或游戏状态。

## 验收标准

- 默认页面第一眼显示原色 RGB24，只有空间采样范围控件可操作。
- 初始 URL 参数不会制造任何进度；改变采样百分比后才解锁后续步骤。
- 切换到调色板会打开位深控件，实际调低位深才会完成颜色步骤；格式选择会完成格式步骤；计算器在此之前保持锁定。
- 计算器只显示原始位数和原始字节，并明确说明压缩格式的实际大小取决于图像内容和编码器设置。
- 采样、颜色、相位、视图、源图上传、重建画布和像素详情继续使用原有确定性模型与兼容情境。
- 恢复初始情境、情境 URL 变化和成功上传都会清空四步流程的进度；失败上传不清空进度。
