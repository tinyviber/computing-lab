# 图像编码：四步引导流程

## 设计目标

图像编码保留真实的图像模型：源图像经过空间采样，再经过颜色表示，最后生成同尺寸重建图像。页面用一个 feature-local 的四步流程安排操作顺序，让第一次进入页面的人先只处理一个变量，再逐步比较颜色表示、格式和数据量。

页面不判断学生是否“学会”。每一步只由实际操作解锁下一步；页面状态记录的是控件是否已经被操作过，不是答题分数。

## 四步操作

| 步骤 | 操作                                               | 解锁规则                                               |
| ---- | -------------------------------------------------- | ------------------------------------------------------ |
| 1    | 改变空间采样百分比，观察采样尺寸和重建图像         | 初始唯一可操作的课程控件；采样百分比发生真实变化后完成 |
| 2    | 先切换到调色板，再调低颜色位深，观察颜色层次       | 第 1 步完成后开放；把调色板位深调低后完成              |
| 3    | 编辑宽度、高度或每像素位数，计算原始位数和原始字节 | 第 2 步完成后开放；编辑任一字段后完成                  |
| 4    | 联系实际文件格式，讨论原始数据量与文件大小的边界   | 第 3 步完成后显示为“可讨论”；不把点击按钮当作理解证明  |

第 1 步之前，采样网格相位、视图标签、画布位置选择、颜色表示和计算器都会显示为锁定状态，并且事件处理也会拒绝这些操作。上传从一开始就可用，因为它是更换实验素材，不是课程步骤。第 1 步完成后，视图、画布位置选择和相位开放；颜色控件仍等到第 2 步开始。第 2 步完成后开放原始数据计算器；编辑过一个计算器字段后，显示第 4 步的文件格式边界讨论。

默认颜色表示是原色 RGB24，所以初始图像不是调色板图像。解析器仍接受旧链接中的 `color=palette`，但统一按 RGB24 初始；序列化时不再写入 `color` 参数，因此 URL 不能伪造颜色进度。通常要先完成采样，再切到调色板并把位深调低；如果情境已经是合法的 1 位深，切换到调色板本身即可完成颜色步骤。旧的 `image=gradient`、`image=checkerboard`、`image=text-edge`、`image=pixel-grid` 和 `scenario=low-sampling` 等情境参数仍用于复现实验配置。

## 状态和重置

`src/features/image-encoding/lesson/state.ts` 只在本功能内保存 `samplingChanged`、`colorAdjusted` 和 `calculatorEdited`。Reducer 会在动作入口检查前置步骤，因此直接派发一个锁定动作也不能跳过顺序。

- URL 只提供样例、采样值、位深、相位和视图等配置，不提供进度；旧的颜色参数只兼容读取，统一回到 RGB24，且不会被重新写回 URL。
- 采样值与当前值相同的事件不会伪造第 1 步完成；键盘和触摸范围控件产生的真实值变化同样有效。
- 恢复初始情境、URL 情境变化和成功载入图片都会清空三项操作进度。上传成功后颜色表示回到 RGB24，仍需重新改变采样百分比；上传失败只显示错误，不改变当前实验。
- 上传输入从首屏可用，成功上传后重新开始本节的解锁流程。

## 图像模型的观察点

- 采样后的编码单元数量会变少，重建图像仍保持源图像的显示尺寸；这不是 CSS 缩放。
- 调色板模式用 `b` 位颜色编号，最多有 `2^b` 个颜色。RGB24 模式直接保留三个 8 位颜色通道。
- 视图和像素详情在第 1 步完成后可用，帮助比较源坐标、采样格、颜色表示和二进制值。
- 相位只在相应方向没有达到完整采样密度时起作用；完整密度的方向固定为 0。

## 数据量和格式边界

原始像素数据量使用明确公式，且不依赖文件格式：

```text
rawBits = sampledWidth × sampledHeight × bitsPerPixel
rawBytes = ceil(rawBits / 8)
```

模型里的 `rawPayload` 和计算器结果是理论像素数据量，不是浏览器生成的 PNG、JPEG 或 WebP 文件大小。第 4 步只用文字说明不同文件格式的边界，页面不为压缩格式编造字节数。

PNG、JPEG 和 WebP 的实际文件大小会受图像内容、编码方式、编码器设置、文件头、颜色表、元数据和具体格式实现影响。计算器会安全地把空值、非数字、非整数和超出范围的输入归一化后再计算，并显示准确的原始位数和原始字节。第 3 步在用户编辑过至少一个计算器字段后标记为完成；第 4 步显示这个边界问题供讨论，不提供压缩字节数估算，也不显示“已完成”。

## 保留的兼容能力

页面仍保留固定样例、兼容情境 URL、本地图片上传、源图和重建图对比、采样/量化/表示/差异视图、相位几何说明和像素详情。它们服务于四步流程，但没有额外的连续任务清单、观察轨迹或全局课程运行时。
