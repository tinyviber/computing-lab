# 图像编码：任务驱动学习流程

## 产品判断

当前实验的计算模型已经足够清楚：源图像 → 空间采样 → 颜色量化 → 索引 bits → 同尺寸重建。主要问题不在“少一个控件”，而在学生进入页面后不知道：

1. 我现在要完成什么任务？
2. 哪个动作能产生哪条证据？
3. 看见现象之后，怎样把现象解释成计算机原理？

因此，页面采用“任务单 + 试验台 + 深挖 + 迁移解释”的结构。任务单负责给方向，试验台负责让证据出现，深挖负责解释底层机制，最后的讨论题负责把操作经验转成可迁移的知识。

## 同类产品调研后的设计取舍

- [Brilliant](https://brilliant.org/) 的核心启发是 learn by doing：短步骤、可操作、即时反馈；但本项目不照搬连续答题卡，而是保留真实实验的开放探索。
- [PhET](https://phet.colorado.edu/en/about) 强调直觉控件、隐性支架、动态可见的内部模型和“像科学家一样探索”；这对应本项目的同尺寸对比、证据视图和像素检查器。
- [Codecademy](https://www.codecademy.com/) 的课程目录和路径感适合借鉴到实验目录，但本项目避免把章节压缩成“下一题”按钮，而是让学生可以回到任意变量重新验证。

## 前端信息架构

### 全站层

- 首页：品牌说明、推荐起点、主题分组、实验数量和本地运行状态。
- 顶部栏：当前实验名称、章节上下文、学习状态。
- 左侧栏：实验目录；进入某个章节后，追加该章节自己的学习路径。
- 移动端：左侧栏收为抽屉，任务单和证据卡片保持单列阅读。

### 图像编码章节层

1. **任务单**：先给情境和待交付的解释，不先揭示结论。
2. **观察重建**：改变一个变量，比较源图与同尺寸重建图。
3. **追踪 bits**：从一个显示像素追踪到采样格、调色板索引和 bit 串。
4. **迁移解释**：比较不同取舍，解释理论载荷与 PNG/JPEG 文件大小的边界。

## 20 分钟课堂任务单

任务单一共 10 项，其中 6 项是“探索解锁”，由网页操作产生客观证据；4 项是“讨论 / 书面”，避免把看到现象误认为已经掌握原理。

| 编号 | 任务                                           | 类型        | 解锁证据                                       |
| ---- | ---------------------------------------------- | ----------- | ---------------------------------------------- |
| 1    | 预测：如果采样变少，哪一种信息会先消失？       | 讨论 / 书面 | 先写下预测                                     |
| 2    | 把空间采样调到 50% 以下，并记录重建尺寸。      | 探索解锁    | 采样参数发生变化                               |
| 3    | 在采样重建视图中圈出一种空间损失。             | 探索解锁    | 访问采样视图                                   |
| 4    | 把颜色位深调到 2 位，并数一数可用状态。        | 探索解锁    | 位深变为 2 位或更低                            |
| 5    | 在量化重建视图中找出一种颜色损失。             | 探索解锁    | 访问量化视图                                   |
| 6    | 点击一个像素，追踪它最终写入的索引 bits。      | 探索解锁    | 访问编码视图并点击像素                         |
| 7    | 用公式核对编码载荷：采样宽 × 采样高 × 位深。   | 探索解锁    | 访问编码表示并改变位深                         |
| 8    | 同样的载荷能否换来不同的图像观感？             | 讨论 / 书面 | 比较两种参数取舍                               |
| 9    | 为什么 PNG/JPEG 文件大小不能直接套用本页公式？ | 讨论 / 书面 | 说明文件头、调色板、元数据或压缩等边界         |
| 10   | 用 80 字解释图像编码做了哪几次取舍。           | 讨论 / 书面 | 写出“源图 → 采样 → 量化 → bits → 重建”的因果链 |

### 推荐时间分配

- 0–2 分钟：阅读情境，完成第 1 题预测。
- 2–8 分钟：只动空间采样，完成第 2、3 题。
- 8–13 分钟：固定采样，再动颜色位深，完成第 4、5 题。
- 13–17 分钟：切换编码表示并点击像素，完成第 6、7 题。
- 17–20 分钟：两人讨论第 8、9 题，课后完成第 10 题。

## 深度探索内容

深挖内容不作为“通关门槛”，而是作为学生继续追问时的原理索引：

- **采样不是网页缩放**：编码单元数量减少，重建时再铺回原显示尺寸。
- **位深是索引状态数**：每个采样像素使用 `b` 位索引，最多对应 `2^b` 个调色板状态。
- **像素到 bits 的追踪**：显示坐标不一定等于采样坐标，检查器把坐标映射和索引表示并置展示。
- **理论载荷的边界**：`采样像素数 × 位深` 是原始像素载荷，不等于 PNG/JPEG 容器的最终字节数。

## 当前实现的交互映射

任务单通过 feature-local 的 `ExplorationTrace` 记录六种行为：改变空间采样、访问采样视图、改变位深、访问量化视图、访问编码视图、点击像素。它只负责显示学习证据进度，不改变图像编码领域模型，也不引入全局的通用 LessonRuntime。

这样做的好处是：学生可以自由探索，URL 场景和纯计算模型仍然可复现；同时页面终于能回答“我已经发现了什么、下一步还应该观察什么”。

## 下一轮建议

1. 为第 8–10 题增加可选的文本记录框，并支持导出任务单报告。
2. 增加两个“同载荷不同取舍”的固定预设，避免学生需要手动搜索参数组合。
3. 将相同的“任务单 / 探索证据 / 深挖”模式抽象成产品级导航契约，但不要把不同实验的领域模型强行抽象成同一个模拟器。
4. 用真实学生做一次 20 分钟可用性观察，重点记录他们是否能在没有教师口头提示的情况下完成第 2、4、6 题。
