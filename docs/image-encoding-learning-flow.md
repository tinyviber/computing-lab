# 图像编码：任务驱动学习流程

## 产品判断

当前实验的计算模型已经足够清楚：源图像 → 空间采样 → 颜色量化 → 索引 bits → 同尺寸重建。主要问题不在“少一个控件”，而在学生进入页面后不知道：

1. 我现在要完成什么任务？
2. 哪个动作能产生哪条证据？
3. 看见现象之后，怎样把现象解释成计算机原理？

因此，页面采用“任务单 + 试验台 + 原理说明 + 联系实际”的结构。任务单负责给方向，试验台负责让变化出现，原理说明负责在观察之后把计算过程讲清楚，最后的讨论题负责把操作经验转成能用于其他问题的知识。

页面区分三件事：网页动作、相关证据出现、学生完成任务并形成理解。达到目标参数、打开编码表示或点击像素后，页面只显示相关证据已出现；学生仍需记录、描述、计算或解释，网页不判断任务完成，也不判断已经学会。证据 trace 属于 Image Encoding feature-local 状态，不是通用课程运行时。

## 同类产品调研后的设计取舍

- [Brilliant](https://brilliant.org/) 的核心启发是 learn by doing：短步骤、可操作、即时反馈；但本项目不照搬连续答题卡，而是保留真实实验的开放探索。
- [PhET](https://phet.colorado.edu/en/about) 强调直觉控件、隐性支架、动态可见的内部模型和“像科学家一样探索”；这对应本项目的同尺寸对比、观察视图和像素检查器。
- [Codecademy](https://www.codecademy.com/) 的课程目录和路径感适合借鉴到实验目录，但本项目避免把章节压缩成“下一题”按钮，而是让学生可以回到任意变量重新验证。

## 前端信息架构

### 全站层

- 首页：品牌说明、主题分组、实验数量和本地运行状态；不默认推荐某一个实验。
- 顶部栏：当前实验名称、实验上下文。
- 左侧栏：实验目录；课程流程由具体实验自己组织。
- 移动端：左侧栏收为抽屉，任务单和证据卡片保持单列阅读。

### 图像编码章节层

1. **任务单**：先给情境和待交付的解释，不先揭示结论。
2. **观察重建**：改变一个变量，比较源图与同尺寸重建图。
3. **看像素怎样变成数字**：从一个显示像素找到采样格、颜色编号和二进制数字。
4. **联系实际**：比较不同取舍，说明原始数据量为什么不等于 PNG/JPEG 文件大小。

这四项只是页面目录，不表示当前阶段、完成状态或强制导航顺序。

## 20 分钟课堂任务单

任务单一共 10 项，其中 6 项会由网页操作产生客观证据；4 项是“讨论 / 书面”。证据不等于任务完成，也不等于已经学会：每次证据出现后，学生仍需按任务要求记录、描述、计算或解释。

| 编号 | 任务                                                         | 类型        | 网页显示的证据                                                           |
| ---- | ------------------------------------------------------------ | ----------- | ------------------------------------------------------------------------ |
| 1    | 预测：如果采样变少，哪一种信息会先消失？                     | 讨论 / 书面 | 先写下预测                                                               |
| 2    | 把空间采样调到 50% 以下（例如 25%），并记录采样后的宽 × 高。 | 页面反馈    | 真实拖动达到 `< 50%`，页面保留这个记录                                   |
| 3    | 在采样重建视图中记录一种变化。                               | 页面反馈    | `< 50%` 目标记录 + 访问采样视图                                          |
| 4    | 把颜色位深调到 2 位。                                        | 页面反馈    | 真实拖动达到 `=== 2`，页面保留这个记录                                   |
| 5    | 在量化重建视图中记录一种变化。                               | 页面反馈    | `2 bit` 目标记录 + 访问量化视图                                          |
| 6    | 打开编码表示并点击一个像素。                                 | 页面反馈    | 访问编码视图 + 点击像素                                                  |
| 7    | 用公式核对一遍原始数据量。                                   | 页面反馈    | 访问编码表示 + `2 bit` 目标；只开放公式记录                              |
| 8    | 同样的原始数据量能否换来不同的图像观感？                     | 讨论 / 书面 | 比较两种参数取舍                                                         |
| 9    | 为什么 PNG/JPEG 文件大小不能直接套用本页公式？               | 讨论 / 书面 | 说明文件头、调色板、元数据或压缩等边界                                   |
| 10   | 用 80 字解释图像编码做了哪几次取舍。                         | 讨论 / 书面 | 按“源图 → 采样 → 颜色数量 → 二进制数字 → 还原图”说明每一步如何造成下一步 |

### 推荐时间分配

- 0–2 分钟：阅读情境，完成第 1 题预测。
- 2–8 分钟：只动空间采样，完成第 2、3 题。
- 8–13 分钟：固定采样，再动颜色位深，完成第 4、5 题。
- 13–17 分钟：切换编码表示并点击像素，完成第 6、7 题。
- 17–20 分钟：两人讨论第 8、9 题，课后完成第 10 题。

## 深度探索内容

深挖内容不作为“通关门槛”。每项解释默认关闭，且只有对应观察出现后才显示；这样它是对现象的进一步说明，不是提前给答案：

- **采样不是网页缩放**：编码单元数量减少，重建时再铺回原显示尺寸。
- **位深是可用颜色数**：每个采样像素使用 `b` 位编号，最多对应 `2^b` 个颜色。
- **像素怎样变成二进制数字**：显示位置不一定等于采样位置，检查器把位置对应关系和颜色编号并置展示。
- **原始数据量的边界**：`采样像素数 × 位深` 是原始像素数据量，不等于 PNG/JPEG 文件的最终字节数。

## 当前实现的交互映射

任务单通过 feature-local 的 `ExplorationTrace` 记录目标参数是否由真实拖动达到、是否访问相关视图、是否点击像素。目标记录会保留：调回原值不会抹掉已经出现的观察。初始 URL 的参数只用于复现实验，不伪造目标记录。

记录在首次加载、样例切换、成功或失败的上传选择、URL 情境改变和恢复样例时清空；普通切换视图不清空。它只负责显示观察记录，不改变图像编码领域模型，也不引入全局的通用课程运行时或答案判断器。

页面可回答“哪些观察证据已经出现”，但不会声称学生已经完成描述、解释或计算。

## 下一轮建议

1. 为第 8–10 题增加可选的文本记录框，并支持导出任务单报告。
2. 增加两个“同样原始数据量、不同取舍”的固定预设，避免学生需要手动搜索参数组合。
3. 等第二个真实课程 consumer 出现，并有行为数据证明共同 navigation invariant 后，再评估是否需要 shared flow abstraction。
4. 用真实学生做一次 20 分钟可用性观察，重点记录他们是否能在没有教师口头提示的情况下完成第 2、4、6 题，以及是否必须通过实验才能说出第 3、5、7 题结论。
